# 百岳離線路線資訊庫

本目錄用於來源整理與後續審閱，三份批次 JSON **仍未由網站或 API 直接載入**。2026-10-26 已人工選錄其中八條路線的部分事實，另整理成 `src/plan/library-sheipa-next.ts` 與 `src/plan/library-central-next.ts` 納入現行範本；這不是 JSON 全量匯入或自動同步。每條路線仍以方向、範圍與版本區分，不把百岳山峰數、路線版本數及可直接使用的計畫數混算。

2026-10-27 另建立 [`biji-gpx-candidates.json`](biji-gpx-candidates.json)：逐筆記錄原頁、作者、記錄／提供日期、頁面里程、本機 XML 結構檢查及與現行範本的版本差異。已下載的原始 GPX 留在使用者 Downloads，**沒有複製進版本庫，也沒有接入網站地圖**。公開頁面只可提供來源連結與使用者自行本機匯入；取得軌跡權利人及必要的平台公開再利用授權、核對路線及路點後，才能評估內建軌跡。健行筆記[服務條款](https://biji.co/privacy/)允許平台在約定範圍使用會員內容，並未授權本工具重發他人的 GPX；下載入口本身不是公開轉載許可。

候選表目前有 6 筆供原站連回與私下比對。雪山西稜的四日軌跡不支援本站六日分日；八大秀另看過的 2026 四日 GPX 只有 1 個命名路點，故未放入公開候選表。另有一組 2025 八大秀四日 GPX 自述中央至白洋缺錄，且每日時間與三峰版本不符，同樣不作範本時間。現行雪山西稜、大小劍及八大秀三個分日版本暫停一鍵套用，詳細原因見[路線合理性審查](../../docs/research/ROUTE_FEASIBILITY_2026-10-27.md)。

候選表的 `sourcePagePlaces` 只是軌跡頁標題／描述實際提到的地名，**不是已核對 GPX 路點名稱或精確座標**。後續可逐筆追加新候選，保留每條軌跡自己的方向、日期、幾何結構與權利狀態。軌跡的花費時間屬作者該次紀錄；範本分段參考仍用獨立的來源紀錄。上河時間須先核對對應原始圖幅和版次，並取得適用的使用權，不能用 GPX 實走時間代稱。候選軌跡目前都沒有公開再利用授權。

本機檢查新候選可執行 `npm run inspect:gpx -- /絕對路徑/路線.gpx`。指令只讀指定檔案，不上傳、不改檔、不儲存座標；輸出 JSON 的 `fileInspection` 可填入候選表同名欄位，另列去除常見自動編號後的 `namedWaypoints` 與缺漏提示。單檔上限 16 MiB、軌跡點上限 100,000；大型檔案須另作人工檢查。GPX 中有命名路點仍需對照原站、來源版本與現地紀錄，不會自動成為範本位置或公開內建軌跡。

## 四組紀錄

| 集合 | 一筆代表什麼 | 主要界線 |
| --- | --- | --- |
| `routes` | 一個明確進出方向與範圍的路線版本 | `orderedStops` 是主要節點順序，`stopsScope=major_waypoints`；不是逐步導航、完整 GPX 或已核准分日計畫。 |
| `segments` | 一份來源直接列明的一段方向與參考／實走記錄 | 目前選錄部分分段；未涵蓋路線的其他路段，不能將已填值加總當完整行程。`day=null` 表示尚無足夠證據分日。 |
| `waypoints` | 某路線下的一筆路點或水源／住宿來源紀錄 | 同一山屋跨路線可重複關聯，不等於新增一處設施。沒有因同名便合併座標，也不把山屋位置當取水點。 |
| `sources` | 一個實際可讀的來源及其讀取／再利用範圍 | 只讀到搜尋摘要、登入頁或封鎖頁，不列為正文已讀。公開可瀏覽不代表照片、原文、GPX 均可重發。 |

ID 範圍：`TW-A100–199` 雪山、`TW-A200–299` 中央北中、`TW-A300–399` 玉山與南段；來源各有 `SH-`、`CN-`、`SJ-` 前綴。更名時保留 ID，不用名稱猜配現行網站的官方步道 ID。

## 時程與日期

- `referenceMinutes` 只寫來源直接列明的分段參考；`referenceTimeKind` 區分官方、健筆編輯與上河。沒有把健筆數字改標上河，也不把整天總耗時比例拆段。
- `walkMinutes` 是作者實走紀錄，另有來源及 `walkTimeBasis`，區分含休息／不含休息／未註明；未知保持空白。參考、實走與休息不能互相覆寫。
- 反向、負重、季節不同須保留差別；沒有由公里數、直線或高差推估分鐘。
- `publishedAt`／`sourcePublishedAt` 為原文發布，`observedAt` 為現地日期，`checkedAt` 為來源讀取。只知道一段旅程的日期範圍時寫在備註，不能任選一天作水源觀察日。
- 所有現況仍為 `currentAccess/currentAvailability: unknown`。來源有較新公告或未來生效日期時保留備註，不由某段將開放推論整條縱走現在可通行。

## 水源、住宿與權利

水源資料記錄池、溪、儲水或官方供水記載及其季節限制，不做水質或當天存量判定。宿營區分官方設置、需申請、僅有記錄及未知；有人住過不代表允許紮營。舊三六九、舊觀高工作站、舊登山口與新設施保留各自版本，不用改名接用舊時間。

上河已核對[官方下載索引](https://www.sunriver.com.tw/step2020.htm)與[著作權聲明](https://www.sunriver.com.tw/copyrights.htm)。本次保留原始連結，未取得整批數位化／網站發布的書面同意，也未轉錄整套分段路網。這個缺口不妨礙整理其他已核對事實。健行筆記只摘錄必要事實並保留作者或單位、原文、日期；未複製圖文、照片或下載重發 GPX。官方來源已核實的開放條款保留原頁，尚未核實者留空並採必要事實摘要，不視為原作再發布許可。OSM 另保留 ODbL 顯名。

Excel 的候選上河圖號只按山域與路線主題提供查閱入口，未逐幅核對原圖涵蓋範圍，不能認定圖上包含戒茂斯等新增版本，或能直接提供對應分段。

## 接續補資料

優先補每條 `dataGaps` 中的項目。Facebook 本輪沒有取得可核對正文的山友貼文，不能用搜尋片段當作水情紀錄。使用者後續提供資料時，至少保留：

1. 原文永久連結、作者、發文日、實走日期或區間。
2. 明確起終點與方向、每天通過時間、是否含休息、負重與天氣季節。
3. 取水點位置或原始座標、當日有水／乾涸／水量描述，取水繞行與主線時間分開。
4. 過夜地點、當時設施狀況、申請／核准依據；不要保存公開隊員名單或私人電話。
5. 原始 GPX、照片及作者分別允許的利用範圍；未回覆保持未詢問，不標成同意。

驗證以 ID 唯一、路線／來源關聯、數值口徑、座標範圍、未知值及 Excel 重讀為主。結果放在輸出目錄的 `support/verification.json`；這不能證明現場路況、供水、精度或許可。
