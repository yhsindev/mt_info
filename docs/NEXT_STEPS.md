## 上線前

1. 以自己的氣象署會員授權碼取得授權產品，保存去識別化 fixture，逐一核對最新欄位、因子、發布時間、有效時段與異常回應。授權碼只放伺服器環境變數。
   QPESUMS 另核實格點原點、座標系統、網格方向與缺測值，驗證定位後才啟用雨量格點繪製。
2. 向管理單位確認 PAC／急救箱位置、實際放置處、使用限制與最後查核時間。補座標時記錄座標來源與精度，不用山屋位置假稱設備精確位置。
3. 逐份完成資料、底圖與圖磚服務授權核對；保留顯名與原文連結。若要加入自行研判預報、警報或診斷治療用途，先另行評估具體功能的要求。
4. 選定部署平台後配置可寫持久快取、單一共用排程及失敗監測；現有本機排程需要 API 持續運行。AED 鎖只協調同一檔案系統，路況／CAP 尚非多程序共用排程；多實例部署前先解決協調。確認日誌不包含金鑰與精確定位。
5. 實機補測 iOS Safari、Android Chrome、觸控地圖、讀屏與定位拒絕／逾時；用受控網路條件測弱網及完整離線，記錄實際行為。

## 資料擴充

- 2026-10-19 已完成全臺 AED 名錄與預設全臺地圖；PAC／急救箱仍是少量可追溯的官方公告種子。優先補這兩類的來源與位置查核，不能把未收錄畫成不存在。
- NCDR WATCH 天氣仍須依具體產品確認申請資格、Token、核准範圍、解析度、預報時段及用途；公開一般訂閱 CAP 已介接並處理正式／測試、更新／取消與過期，詳見 [目前覆蓋限制](CONDITIONS.md)。
- 向林業署確認入口 x/y 的官方座標系統，取得文件後再加座標轉換及比對測試；目前路況以文字清單呈現，不猜測點位。路況看板目前以原文適用區域呈現警示，未展示地圖。
- 擴大設備與山區前補人工維護流程、來源變更紀錄及查核責任；人員回報先保留待確認狀態。
- 為真實氣象產品建立來源版本與實際回應契約測試，避免資料欄位變動後誤顯示數值。
- 若要關聯集水區雨量，另定測站涵蓋、時間對齊、格點範圍與缺測規則，明確標示推估方式；不按最近測站推定整個流域雨量。

## 另案規劃

- 任意渡溪點的完整上游分析需 DEM 流向、匯流、水系拓樸及現地／既有水文資料驗證。
- 行前資料包需顯示保存時間與過期狀態；離線底圖另找允許該用途的來源或自行供應，不能大量預載公共圖磚。
- 若增設帳號、足跡或精確位置上傳，再設計告知、同意、保存期限與刪除機制。
